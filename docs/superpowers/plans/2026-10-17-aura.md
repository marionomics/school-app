# Bloque 2 — Aura Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The teacher's aura on a participación *is* its validation, the feed stops reordering on aura, the teacher can veto from the feed, and "like" is renamed "aura" everywhere a person reads it.

**Architecture:** One backend service function, `set_teacher_aura`, writes the teacher's `likes` row and `posts.reviewed_at` together; every teacher entry point (aura button, Validar, Quitar validación, bulk) goes through it. A data-only Alembic migration reconciles existing rows. The frontend gets a pure cache-patching module shared by the aura and veto mutations, and a `useVetoFlow` hook that puts the existing `/revisar` veto dialog on the feed card.

**Tech Stack:** FastAPI + SQLAlchemy + Alembic + pytest (backend); React + Vite + TanStack Query + vitest, shadcn `base-sera` on `@base-ui/react`, `@remixicon/react` (frontend).

**Spec:** `docs/superpowers/specs/2026-10-17-aura-design.md` — read it before starting. The plan argues from it.

## Global Constraints

- The teacher's aura **never gives points**. `award_like` already returns `None` for a teacher; do not change that.
- **Validar never moves points.** `test_reviewing_moves_no_points` (`backend/tests/test_reviewed.py`) is the guard; if it fails, the change is wrong.
- `validar` ≠ `vetar`: two separate controls, never one. Veto keeps its confirmation dialog.
- **No aura bumps `last_activity_at`** — not a student's, not the teacher's. Replies still do.
- Only a **participación** in a class the teacher owns is validated by their aura. Aura on anything else is plain aura.
- The API keeps its `like` names (`/like`, `like_count`, `liked_by_me`, table `likes`, `source_type = "forum_like"`). Only user-facing copy says aura.
- All user-facing text lives in `frontend/src/strings/es.ts` as placeholders; Mario writes final copy.
- Icons only from `@remixicon/react`. Emojis are not UI (👻 and 🥷 are the only exceptions).
- Use the preset components (`@/components/ui/*`) as they are; never restyle a primitive.
- Optimistic updates with visible rollback (toast on failure).
- Modules under `frontend/src/lib/` that have a `*.test.ts` must import with **relative paths**, never `@/` — vitest does not resolve the alias (see R5 in `planning/bugs.md`).
- Backend tests: `cd backend && .venv/bin/python -m pytest -q`. Frontend: `cd frontend && npx tsc -b --noEmit && npx eslint src && npm test && npm run build`. The one existing eslint warning in `src/components/ui/button.tsx` is pre-existing; leave it.
- Each task ends with a commit **and a push to `origin/main`** (Railway deploys `main`; Mario QA's in prod). Commit messages end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.

## Review Focus

1. **Validating twice** (Validar after the aura is already on, or a bulk that includes an already-validated one) must leave `like_count` at +1, not +2, and keep the original `reviewed_at`. → Task 1, `test_validating_twice_counts_one_aura`.
2. **Quitar validación on a participación with `reviewed_at` but no like row** (old data, or the migration not yet applied) must not push `like_count` below its real value. → Task 1, `test_unvalidating_without_a_like_row_keeps_the_count`.
3. **Validating a vetoed participación** from the handled list in `/revisar` must keep like and `reviewed_at` in sync and still move no points. → Task 1, `test_validating_a_vetoed_participacion_stays_in_sync_and_moves_no_points`.
4. **Aura on a pinned tarea** ("Por entregar" at the top of the feed): the optimistic flip must reach the `pinned` list too, or the button looks dead until a refresh. → Task 4, `mapFeed` test "patches pinned as well as items".
5. **The feed staying stale after validating in `/revisar`**: the teacher validates there, goes back to the feed, and the aura must show as on. → Task 4, Revisar's review mutations invalidate `["feed"]` (checked in the Task 4 manual step).

```python
from sqlalchemy.orm import Session

from app.models import Class, Like, Post, User, utcnow


def _validates(db: Session, post: Post, teacher: User) -> bool:
    """Only a participación in a class this teacher owns is validated by
    their aura. Anywhere else the aura is just aura."""
    if post.type != "participacion" or post.class_id is None:
        return False
    klass = db.get(Class, post.class_id)
    return klass is not None and klass.teacher_id == teacher.id


def set_teacher_aura(db: Session, post: Post, teacher: User, on: bool) -> None:
    """The teacher's aura and validation are one fact, stored in two places:
    the like row and posts.reviewed_at. This is the only writer of both, so
    they cannot drift apart.

    Moves no points (a teacher's like never earned any — award_like) and never
    touches last_activity_at. Idempotent. Does not commit: the caller does,
    so the bulk endpoint stays all-or-nothing.
    """
    existing = (
        db.query(Like)
        .filter(Like.user_id == teacher.id, Like.post_id == post.id)
        .first()
    )
    if on and existing is None and post.author_id != teacher.id:
        db.add(Like(user_id=teacher.id, post_id=post.id))
        post.like_count += 1
    elif not on and existing is not None:
        db.delete(existing)
        post.like_count = max(0, post.like_count - 1)

    if not _validates(db, post, teacher):
        return
    if on:
        if post.reviewed_at is None:      # keep the first time it was seen
            post.reviewed_at = utcnow()
            post.reviewed_by = teacher.id
    else:
        post.reviewed_at = None
        post.reviewed_by = None
```

```python
"""teacher aura validates (data only)

The teacher's aura on a participación and its validation became one fact in
Bloque 2. This fills in whichever half is missing on existing rows so the
two never disagree: validated posts get the teacher's like, and liked posts
get reviewed_at. Never a self-like; never touches last_activity_at.

Revision ID: d4a1f7c2e9b3
Revises: c02ad66222b5
Create Date: 2026-10-17
"""
from typing import Sequence, Union

from alembic import op
import sqlalchemy as sa

revision: str = "d4a1f7c2e9b3"
down_revision: Union[str, Sequence[str], None] = "c02ad66222b5"
branch_labels: Union[str, Sequence[str], None] = None
depends_on: Union[str, Sequence[str], None] = None

# Validated participaciones of a class whose teacher has not liked them yet.
_MISSING_LIKE = """
    FROM posts p JOIN classes c ON c.id = p.class_id
    WHERE p.type = 'participacion'
      AND p.reviewed_at IS NOT NULL
      AND p.author_id <> c.teacher_id
      AND NOT EXISTS (SELECT 1 FROM likes l
                      WHERE l.post_id = p.id AND l.user_id = c.teacher_id)
"""


def upgrade() -> None:
    bind = op.get_bind()
    # 1a. Count first, while the predicate still selects exactly these posts.
    bind.execute(sa.text(
```

```ts
import type { InfiniteData, QueryClient } from "@tanstack/react-query";
import type { FeedPage, Post, ThreadResponse } from "./types";

/** Optimistic aura. A teacher's tap also flips the visible "profe" mark;
 *  a student's never does. */
export function toggleAura(p: Post, viewerIsTeacher: boolean): Post {
  const on = !p.liked_by_me;
  return {
    ...p,
    liked_by_me: on,
    like_count: Math.max(0, p.like_count + (on ? 1 : -1)),
    teacher_aura: viewerIsTeacher ? on : p.teacher_aura,
  };
}

const patch = (id: number, fn: (p: Post) => Post) => (p: Post) =>
  p.id === id ? fn(p) : p;

/** Pinned too: a tarea under "Por entregar" is the same post. */
export function mapFeed(
  data: InfiniteData<FeedPage> | undefined,
  id: number,
  fn: (p: Post) => Post,
): InfiniteData<FeedPage> | undefined {
  if (!data) return data;
  return {
    ...data,
    pages: data.pages.map((pg) => ({
      ...pg,
      items: pg.items.map(patch(id, fn)),
      pinned: pg.pinned.map(patch(id, fn)),
    })),
  };
}

export function mapThread(
  t: ThreadResponse | undefined,
  id: number,
  fn: (p: Post) => Post,
): ThreadResponse | undefined {
  if (!t) return t;
  return { post: patch(id, fn)(t.post), replies: t.replies.map(patch(id, fn)) };
}

/** Applies fn to this post wherever it is cached and returns the rollback. */
export async function patchPostInCaches(
  qc: QueryClient,
  post: Post,
  fn: (p: Post) => Post,
): Promise<() => void> {
  const feedKey = ["feed"];
  const threadKey = ["thread", String(post.parent_id ?? post.id)];
  await qc.cancelQueries({ queryKey: feedKey });
  const prevFeed = qc.getQueryData<InfiniteData<FeedPage>>(feedKey);
  const prevThread = qc.getQueryData<ThreadResponse>(threadKey);
  qc.setQueryData<InfiniteData<FeedPage>>(feedKey, (d) => mapFeed(d, post.id, fn));
  qc.setQueryData<ThreadResponse>(threadKey, (t) => mapThread(t, post.id, fn));
  return () => {
    if (prevFeed) qc.setQueryData(feedKey, prevFeed);
    if (prevThread) qc.setQueryData(threadKey, prevThread);
  };
}
```

```tsx
import { useState } from "react";
import { useMutation, useQueryClient } from "@tanstack/react-query";
import VetoDialog from "@/components/VetoDialog";
import { useToast } from "@/components/Toaster";
import { patchPostInCaches } from "@/lib/postCache";
import { setVeto } from "@/lib/review";
import { es } from "@/strings/es";
import type { Post } from "@/lib/types";

/** Veto from the feed or a thread: confirm before vetoing, never before
 *  lifting a veto (that is the safe direction). Optimistic, with rollback. */
export function useVetoFlow() {
  const qc = useQueryClient();
  const toast = useToast();
  const [confirming, setConfirming] = useState<Post | null>(null);

  const m = useMutation({
    mutationFn: ({ post, vetoed }: { post: Post; vetoed: boolean }) =>
      setVeto(post.id, vetoed),
    onMutate: async ({ post, vetoed }) => ({
      rollback: await patchPostInCaches(qc, post, (p) => ({
        ...p,
        status: vetoed ? "vetoed" : "active",
      })),
    }),
    onError: (_e, _v, ctx) => {
      ctx?.rollback();
      toast.show(es.revisar.saveError);
    },
    onSettled: () => {
      for (const k of ["feed", "thread", "review-participaciones", "grade"])
        void qc.invalidateQueries({ queryKey: [k] });
    },
  });

  const request = (post: Post) =>
    post.status === "vetoed"
      ? m.mutate({ post, vetoed: false })
      : setConfirming(post);

  const dialog = (
    <VetoDialog
      open={confirming != null}
      onCancel={() => setConfirming(null)}
      onConfirm={() => {
        if (confirming) m.mutate({ post: confirming, vetoed: true });
        setConfirming(null);
      }}
    />
  );

  return { request, dialog };
}
```
